WEEK 08

教 AI 做事的方法：AI Agent 與設計模式

AI Agent 的四種設計模式：反思、工具、規劃、多代理合作。

  • AI Agent
  • Tool Use
  • Vibe Coding

01本週一句話

AI Agent 就是教 AI 用我們的方法做事：像人一樣會規劃、查資料、用工具，寫完還會再改。

02重點整理

什麼是 Agent

教科書的定義是：能透過感測器感知環境、透過致動器採取行動的實體。這門課的定義更直接：AI Agent = AI Model + Harness，也就是教 AI 照我們做事的方法做事。

為什麼一次生成不夠

直接下 prompt 等於要人一口氣寫完文章，不能刪、不能改。人都是邊寫、邊試、邊改，還會查資料、按計算機。RAG 自動找資料，其實就是一種 agent。

Reflection 反思

第一個 LLM 寫初稿，第二個 LLM 當評論員給改善建議，第一個再修改，可以重複好幾輪。評論員也可以換成不同的模型。

Tool Use 使用工具

LLM 不擅長的事（精確計算、即時數據、上網搜尋）就交給工具。LLM 決定要呼叫哪個函式，拿回 JSON 結果，再根據結果回答。MCP 標準化 agent 使用工具的方式，A2A 則定義 agent 之間怎麼溝通。

Planning 與多代理合作

先請 LLM 想一想、打草稿再回答，例如思維鏈（CoT）；DeepSeek-R1 會把思考包在 <think> 標籤裡。複雜任務可以由一個像 PM 的 LLM 拆解，分派給多個 agent 分工。

Vibe Coding

Karpathy 在 2025 年 2 月創的詞：忘了程式碼的存在、不看 diff、有錯就直接貼給 AI。適合週末小專案和原型，不適合要正式上線、出錯會有後果的程式。

03核心公式

吳恩達提出的四種 AI Agent 設計模式：

模式一句話例子
Reflection寫完請別人評論，再改作者 LLM ⇄ 評論員 LLM
Tool Use不會的事交給工具計算機、搜尋、資料庫、MCP
Planning先規劃，再動手思維鏈（CoT）、推理模型
Multiagent分工合作PM 拆任務，各 agent 負責一塊

Tool Use 範例：飲料店 ChatBot（使用者說「我想訂 20 杯麥茶」）

使用者問題→LLM 選工具→quote_order("麥茶", 20)→JSON 結果→「沒問題！共 600 元」
{
        "item_name": "麥茶",
        "quantity": 20,
        "unit_price": 30,
        "total": 600,
        "stock": 30
      }

Karpathy 認為 AGI 還要大約十年，現在的 AI 還不像真正的人類實習生。另外，他對 Vibe Coding 的看法常被誤讀：他自己也說這只適合拿來玩、出錯沒關係的專案。

04名詞小辭典

AI Agent
能自己規劃、使用工具、多步驟完成任務的 AI。
Harness
模型以外的工作裝備，讓 AI 能真的動手做事。
Reflection（反思）
讓 LLM 評論自己或別人的輸出，再修改。
Tool Use / Function Calling
LLM 決定呼叫哪個函式，並用回傳的結果回答。
MCP
Anthropic 提出的協定，標準化 AI 與外部工具、資料的連接方式。
A2A
Google 提出的協定，定義 agent 與 agent 之間怎麼溝通。
思維鏈（Chain-of-Thought）
先把思考步驟寫出來，再給答案。
Vibe Coding
完全交給 AI 寫程式、自己不看程式碼的開發方式。

05自我測驗

Q1. 為什麼說 RAG 也是一種 AI Agent？

原本要人自己找資料，RAG 讓電腦自動檢索相關資訊再交給 LLM，也就是 AI 照我們的方法多做了一步。

Q2. Tool Use 中，LLM 參與了哪兩個階段？

第一，決定要呼叫哪個工具、帶什麼參數；第二，拿到工具回傳的資料後，整理成給使用者的回答。

Q3. Vibe Coding 適合用在哪裡？不適合用在哪裡？

適合週末小專案、試做原型；不適合要正式上線、出錯會造成問題的程式。

06我的心得

四種設計模式其實就是好員工的工作習慣：先規劃、會用工具、寫完自我檢查、懂得分工。

這個網站本身也算一次小小的 agentic 練習：我寫好規則，AI 照規則一頁一頁做出來，我負責檢查。
